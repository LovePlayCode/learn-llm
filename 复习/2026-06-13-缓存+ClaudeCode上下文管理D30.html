SECTION 01 ─── 缓存 · 两道生死题重焊

D30 验证：在线教育 AI 助手缓存设计

场景：三种学生提问——"什么是牛顿第三定律"/"帮我分析我的作文"/"怎么解这道二次函数题"。 用两道生死题作为判断框架，逐一过滤。

两道生死题（重新焊回）

生死题 ①

输出会随时间变化吗？

问时效性。如果今天和明天的答案不同，语义缓存就有过期风险。

生死题 ②

输出依赖私人上下文吗？

问独特性。如果不同用户的相同问法需要不同答案，缓存命中 = 张冠李戴。

三种提问的判断结果

提问 ① 时效性 ② 私人依赖 结论
"什么是牛顿第三定律" 否 否 ✅ 两关都过 → 语义缓存
"帮我分析我的作文" 否 是（绑定具体作文） ❌ 第②关拦下 → 语义/精确不可，提示词缓存可用
"怎么解这道二次函数题" 否 是（"这道"绑定具体题目） ❌ 第②关拦下 → 不适合语义缓存
"这道"的陷阱

初次回答时把"这道二次函数题"判为"有时效性"——其实数学公式不会随时间变。真正的关键是"这道"= 绑定了具体题目 = 私人上下文。时效性 vs 私人依赖的区别需要在提取时分清。

作文题 → 提示词缓存的连接

虽然作文题不能用语义/精确缓存（私人数据），但在一次会话中，作文全文作为不变前缀，后续逐段批改只改后缀——这是提示词缓存的经典命中模式。跨兄弟调取能力 ✓。

SECTION 02 ─── CONTEXT · 开工 4 问实战

D30 验证：作文批改场景的 Context 管理

场景：学生发 2000 字作文 → AI 逐段批改 → 最后整体评价。用"开工 4 问"逐一过一遍。

① 当前任务和上一个任务相关吗？→ 相关，不 /clear

整个会话围绕同一篇作文展开，context 中的信息有连续性。

② 这个动作需要读很多文件吗？→ 否，不开 subagent

单文件场景（一篇作文），不需要并行读取。但追问：如果要调取 10 篇历史作文做趋势分析 → 触发 subagent。

③ 这次改动跨了几个文件？→ 不跨，不用 Plan Mode

所有操作都在同一份文档上进行。

④ 关键信息放在哪里？→ 作文放开头（Lost in the Middle）

2000 字作文是所有后续问答的核心依赖，放在 context 前段避开 U 型注意力塌陷区。

追问：subagent 的触发双条件

触发 subagent 的两个信号：① 任务独立（子任务可以在隔离的 context 里完成）+ ② 需要读多个文件（主 context 装不下或不需要装）。两者同时满足时启动，主 agent 只收摘要。

SECTION 03 ─── 跨章节 · 错误累积 × TCC

D30 验证：解题链 + checkpoint + TCC 归类

场景：AI 助手分 4 步解题，每步正确率 95%。考察错误累积公式 + 降低方案 + TCC 归类。

公式验证 · 通过

1 - 0.95⁴ ≈ 18.55%

错误累积公式 1 - p^N 秒出。4 步 95% 看似很高，但约五分之一的概率翻车。数学肌肉记忆稳。

方案设计 · 通过

动 p + 动结构

方案 A：换更强模型提高 p。方案 B：设检查点切分为局部低阶 N。且落地描述完整：验证器检查 → 错误回传 → 局部重试。

AI 解题 4 步链 · 错误累积分析 成功率：0.95⁴ ≈ 0.815 失败率：1 - 0.815 ≈ 18.55% 降低方案： ┌─ 方案 A：动 p ──── 换更强模型（95% → 99%） │ 1 - 0.99⁴ ≈ 3.9%（降低 14.6 个百分点） │ └─ 方案 B：动结构 ── 每步后插 checkpoint 验证器检查 → 不通过 → 错误信息回传 → 局部重试 本质：把 1 个 N=4 的连续赌注切成 4 个 N=1 + 验证 checkpoint 的工程落地三要素： ① 谁检查 → 验证器模型 ② 检查什么 → 当前步输出是否正确 ③ 不通过怎么办 → 带错误信息的局部重试（非盲重试）

checkpoint = Controllable 的儿子

checkpoint 的全部动作（拦截、回退、重试、局部低阶 N）都是"管得住"的具体实现。已重新焊回。

TCC 三兄弟各管什么（重焊版） Transparent 看得见 → 日志、过程可视化、决策链展示 Controllable 管得住 → checkpoint、重试、打断、回滚、人类审批 Consistency 信得过 → 行为稳定、不矛盾、输出可预期 口诀：checkpoint = Controllable 的儿子

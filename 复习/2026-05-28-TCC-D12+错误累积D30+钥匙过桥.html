CONSISTENCY · 跳层修复

三轮迭代才跳出"产出层"

第 1 轮：效果一致 ❌（在产出层）

控制三件套 · 工程 vs 原义

"可纠错" vs "可指导"的口味

可指导 → 主动告诉它该走哪条路（人类发指令）

可纠错 → 被动修它已经犯的错（错了再补救）

5/16 原词是"可指导"。checkpoint 偏纠错那一面，但 TCC 原义是指导——别记混。

SECTION 02 ─── 错误累积 · 数字直觉

单步 30% · 十步几乎必错

上一轮我留下的硬伤：0.3 × 10 = 3——突破物理学的概率值。今天用乘法定律重算， 把"加法直觉"彻底拔掉、把正确率的 N 次方焊进肌肉。

═══════════════════════════════════════════════════════════════════
                数字直觉 · 完整对账（请念三遍）
═══════════════════════════════════════════════════════════════════

  最初的直觉：     0.3 × 10 = 3        ❌ 「物理学崩塌版」
  修正的公式：     1 - 0.7¹⁰           ✅ 「乘法定律」
  真相数字：       97.18%              🚨 「几乎必错」

  距离 100% 还有：   2.82%
  距离直觉 30%：    ×3.24 倍
  距离 "3"（笑）：   再也回不去了
═══════════════════════════════════════════════════════════════════
  推导链路（焊死这条传递）：

  单步错误率  p = 0.3
        │
        ▼
  单步正确率  1 - p = 0.7
        │
        ▼  乘法定律
  N 步全对率  (1 - p)^N  =  0.7¹⁰  ≈  0.0282
        │
        ▼  补集
  N 步至少错一次  =  1 - (1 - p)^N  ≈  0.9718
                                          ↑
                                   这才是"累积错误率"

为什么 30% 直觉骗人？ 因为大脑天生用加法感知风险（"30% × 10 = 300%? 不对就 100% 吧"）， 但概率世界用的是乘法——错误不是叠加，是"全对" 一次次贬值。

SECTION 04 ─── 跨章节关联 · 传递链

每一跳不能跳步

子问 ④ 第一轮里两条传递链都"模糊掉了"——用泛词"减少错误"代替了"单步错误率 / 累积错误率"的精度。 第二轮重写后，两条链路都讲清了。

链路 A · 自洽性

降的是单步基数

自洽性
  │
  ▼ 单步内多次采样取多数票
单步错误率 ↓ (0.3 → 0.1)
  │
  ▼ 等价表达
单步正确率 ↑ (0.7 → 0.9)
  │
  ▼ 乘法定律
正确率^N ↑ 变大
(0.7^10 = 2.8% → 0.9^10 = 35%)
  │
  ▼ 1 - 上面那个
累积错误率 ↓ 变小
(97.2% → 65%)

关键洞察：自洽性不是直接治累积，是让累积分母变小。

链路 B · RAG

减的是单步错误源

RAG
  │
  ▼ 检索外部知识库
找到与问题相关的事实
  │
  ▼ 注入上下文窗口
喂给模型当输入
  │
  ▼ 模型 grounded 在事实上
减少幻觉
  │
  ▼ 单步错误源 ↓
单步错误率 ↓
  │
  ▼ 乘法定律传导
累积错误率 ↓ 变小

"真实的、有依据的上下文"——你给的这个翻译比术语 grounded 更精准。

SECTION 05 ─── 跨章节连接构建 · 你自己问出的金钩

checkpoint = Control 的工程实现

"设 checkpoint 是为了重跑吗？"——这个问题不是我引导你问的，是你自己问出来的。 它把今天上下半场两个家族图缝在一起：

═══════════════════════════════════════════════════════════════════
   场景 A · 10 步 · 无 checkpoint
   ─────────────────────────────────────────────────────────────
   累积错误率 = 1 - 0.7¹⁰ ≈ 97.18%       🚨 几乎必错
═══════════════════════════════════════════════════════════════════
   场景 B · 10 步 · 第 5 步设一个 checkpoint
   （checkpoint 处「验证 + 纠错」 → 错误率重置为 0）
   ─────────────────────────────────────────────────────────────
   第一段 5 步：1 - 0.7⁵ ≈ 83.2%   →   纠错  →  归零
   第二段 5 步：1 - 0.7⁵ ≈ 83.2%   →   终点

   把「几乎必错」切成「两个还能挽救的小段」 ✂️
═══════════════════════════════════════════════════════════════════
// TypeScript · checkpoint 骨架（5 行核心逻辑）
type AgentState = { /* 任务中间状态 */ };
type Step = (state: AgentState) => Promise<AgentState>;

async function runAgent(steps: Step[]): Promise<AgentState> {
  let state: AgentState = initialState();
  let lastCheckpoint: AgentState = state;            // ① 兜底快照

  for (const step of steps) {
    state = await step(state);                       // ② 单步 LLM 调用 ← 错误累积的儿子

    if (validate(state)) {                           // ③ 可中断 ← Control
      lastCheckpoint = structuredClone(state);       // ④ 可恢复（存档）
    } else {
      state = structuredClone(lastCheckpoint);       // ⑤ 可恢复（读档）
      // 也可在此处呼叫人类介入：human_in_the_loop
    }
  }
  return state;
}
展开 · 三连问的精确映射（语义微调）

Q1 · 哪一行是"每一步的 LLM 调用"？ → ② state = await step(state)。 它就是错误累积家族图里的"儿子"层级。

Q2 · ④⑤ 在 Control 三件套中映射？ → ④ 存档是"可恢复"的前置准备， ⑤ 读档是"可恢复"的实施——两行其实都属于"可恢复"两面。 "可中断"在 ③ 行的 validate 判断里，"可指导"对应的是"也可在此处呼叫人类介入"那一行。

Q3 · 第 7 步失败回滚到第 5 步，累积分母切到几步？ → 5 步。 因为回滚后第 6、7 步的累积被擦除，所有累积链路都从 checkpoint 重新开始，分母永远 ≤ 5。 这才是 checkpoint 治错误累积的核心机制——不是"重跑"，是"把累积分母切短"。

SECTION 01 · 概念辨析闭卷

题 1 + 题 2 · 改策略vs改答案 · 协调层元认知vs质检

题 1 · 元认知 vs 普通纠错（通过）

用"做题"类比：元认知调的是解题思路（方法/标准层），普通纠错只改最终那个答案（结果层）。边界题验证：用同样方法 A 重算、只把 37 改成 39 = 普通纠错；"怀疑算错"只是监控苗头，没升级成换方法就不算元认知。钥匙焊死：方法没变只改结果 = 普通纠错；方法/标准变了 = 元认知。

题 2 · 协调层元认知 vs 质检（从混淆到焊死）

首轮把"协调层元认知"答成"检查输出对不对"——那是质检。经"上下兄弟问三句"修正后归位：上 = 元认知家族（不是纠错家族）；兄 = 质检（同住协调层，但质检查产物、它查策略）；下 = 修改协作策略 / 换更强的模型。这是本次最关键的元层级修复。

协调层元认知 · 上下兄弟分层（题 2 收口版）

第 3 层（家族 / 理念）      元认知 Metacognition
                            = "改策略，不只改答案"（战略级）
                                  │
第 2 层（具体方法 / 兄弟）    ├── 协调层元认知  → 审视「协作策略对不对」
                            │       （分配 / 模式 / Agent 选择）
                            │
                            └── 质检 Quality Check → 审视「产物对不对」
                                    （验收标准 / 边界 / 合规）  ← 兄弟，非它自己

🔑 质检问"东西做对没"，协调层元认知问"我这样安排对没对"。
SECTION 02 · 应用 · Over-Reflection

题 3 · 三个场景判断 + 过度反思代价

(a) 酒店偶尔选错 → 不反思

熟悉任务的常规小错，错的只是输出层，策略没毛病。泛泛的"模型有偏差"可优化为"熟悉任务常规小错，做法本身没问题"。

(b) 新领域首跑不通 → 该反思

执行路径可能全错，需回溯决策、重新生成决策。这是 7/01 曾栽过的坑（当时判成不需反思），今天主动判对。

(c) 用户连说三次不对 → 该反思

连续不满意说明初始决策就偏了，属于策略层问题，需反思。

过度反思 Over-Reflection 的代价（反向追问，答得超出预期）

若错误地对 (a) 也反思：① 成本（反复调模型烧 token）；② 速度（延迟飙升）；③ 循环——"一直在思考改，但第一次方案已经是对的"，把本来对的东西改坏；④ 根因——问题本身不清晰、或根本无解时，再反思也是空转。导出工程护栏：给反思设预算（最多 N 轮）+ 用"错的是答案还是策略"尺子分流。

SECTION 03 · 应用 · 设计元认知模块

题 4 · 无状态三缺失 + 双层级路由

电商客服 Agent 的元认知模块设计（通过）

加 Evaluator + self-Reflection 两个节点：Evaluator 在每个最小任务后评估，self-Reflection 反思后把结果注入执行节点影响决策。 补齐 LLM 无状态三缺失：① 决策历史存储 = Reasoning Chain（存做了啥+为啥）；② 评估机制 = Evaluator；③ 策略切换逻辑 = 注入执行节点。 

元认知模块 · 双层级路由（题 4 收口版）

        ┌──────── 决策历史存储 (Reasoning Chain：做了啥 + 为啥)
        │
执行节点 ──完成最小任务──▶ Evaluator（双层级判断）
                              │
              ┌───────────────┴───────────────┐
         答案层坏                              策略层坏
   （准确性 / 事实性 / 格式 / 约束）      （目标完成度 / 系统健康度）
              │                                 │
         纠错 / 重试                        self-Reflection / 重规划
              │                                 │
              └────────▶ 注入执行节点，影响下一轮决策 ◀──┘

🔑 同一 Evaluator 可看两层，但下游必须分流：答案层 → 纠错，策略层 → 元认知。

关键修正：双层级必须分流

五个评估维度不是一家人：准确性/事实性/格式约束属答案层（触发纠错/重试）；目标完成度/系统健康度属策略层（触发 self-Reflection/重规划）。若答案小错也触发反思，则 7/01 戒掉的 Over-Reflection 循环复燃。Evaluator 判完要"路由"，不能"判完就反思"。

SECTION 04 · 综合 · 跨章节缝合 ⭐

题 5 · 元认知 × 可信赖 Agent × 错误累积

缝合结论（通过）

敌人 = 错误累积 1 − p^N（每步错 p，连走 N 步翻车）。 checkpoint = 安全网：固定位置插暂停点、局部重试、把 N 切成小段。 元认知 = 主动刹车：动态觉察，早发现早止损，比安全网更靠前；它挡住越权 / 过度代理两类输出侧威胁（在坏事发生前拦），并常导向人类审批档（本质即 HITL 版 checkpoint）。 三者合作把 N 压到最小。 

元认知 × checkpoint × 错误累积 三者配合

敌人：错误累积 1 − p^N（每步错 p，连走 N 步翻车）
  │
  ├── checkpoint = 安全网（位置驱动）
  │     在预设固定关口插暂停（如"调外部工具前""支付前"）
  │     到这个点就查，不管当时有没有问题 → 局部重试，把 N 切小段
  │
  └── 元认知 = 主动刹车（信号驱动）
        动态觉察，持续监控策略 / 威胁苗头
        一旦发现越权 / 过度代理征兆就立刻刹
        → 常常比任何固定 checkpoint 都早
        → 常导向「人类审批」档（HITL 版 checkpoint）

配合：元认知能早刹就早刹（主动刹车），
      刹不住或到固定关口还有 checkpoint 兜底（安全网）。
      一个靠前主动，一个固定兜底，合起来把 1−p^N 的 N 压到最小。

前置缺口补救：五类威胁 + 三档安全边界（先忘后捞，锚点生效）

题 5 前发现五类威胁、三档安全边界已遗忘。用"输入/推理/输出"与"能不能反悔"两个锚点成功捞回： 五类威胁 = 提示词注入 · 知识库投毒（输入侧）· 幻觉（推理侧）· 越权 · 过度代理（输出侧）； 三档安全边界 = 自动执行 · 人类审批 · 绝对禁止。 注意"过度代理 = 擅自替用户做太多自主决策"已能说清动作，比 7/07 光说"权限太大"更锋利。

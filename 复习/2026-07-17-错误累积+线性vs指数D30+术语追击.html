SECTION 01 ─── Q1 · 公式默写 + 心算方向感

公式记住了 1− · 心算首判仍偏线性

✅ 公式精度 · 修复

1 − p^N 不再漏 1−

7/9 写成 p^N（漏 1−），今天闭卷直接写出 1 − p^N。从「理解层」往「肌肉层」挪了一步。

p^N 是累积成功率，1 − p^N 才是累积错误率。

🟡 心算方向感 · 首判反了

0.85^12 估成「90%以上」

实际累积错误率 ≈ 86%。答「90%以上」方向对、偏高一点，比 7/9 的「50%」准太多。

但比较题首判翻车：「0.85^12 更大，因为指数更大」——只看指数，漏看底数。

心算比较题 · 两根杠杆：

  0.85¹²   vs   0.9¹⁰
   │              │
   │  底数 0.85 < 0.9   ← 底数更小 → 结果更小（杠杆①）
   │  指数  12  >  10   ← 指数更大 → 结果更小（杠杆②，底数<1时反向）
   │
   └─ 两根杠杆同向压 → 0.85¹² 双重地小于 0.9¹⁰

  实际值：0.85¹² ≈ 0.14   0.9¹⁰ ≈ 0.35

  ┌────────────────┬────────────────┐
  │  线性直觉       │  指数现实       │
  │  指数大→结果大  │  底数<1：指数大→结果小 │
  │  （底数>1 才成立）│  （加 vs 乘）  │
  └────────────────┴────────────────┘
学习者修正后原话：「底数小于 1 时，指数越大，最后的数值越少。」——方向感红点重焊。
SECTION 02 ─── Q2 · 三术语一字不差 · ⭐ 元层级焊死

「动别的」三次摔倒
第四次自己站起来

这是今天的金光时刻。一个元层级薄弱点，5/31 → 7/9 → 7/17 摔了三次， 第四次学习者自己捅破了「杠杆 ≠ 杠杆的效果」那层窗户纸。 

累积错误率治理 · 三兄弟框架（三个平级杠杆）：

  1 − p^N
      │
   ┌──┴──────────┬──────────────┐
  动 N          动 p           动「别的」(checkpoint)
   │            │              │
 砍步数        提精度          切段 + 重试
 直接删一步    换更强模型       插存档点
              /好 prompt       失败可重来

  ┌──────────────────────────────────────────────────┐
  │ checkpoint 既不改 N（步数不减），也不改 p（精度不变）│
  │ 它改的是指数累积的结构 → 局部低阶 N · 截断与降幂 │
  └──────────────────────────────────────────────────┘
① 局部低阶 N · ✅ 首轮

一字不差

闭卷首轮即答出「局部低阶 N」。5/31 自己起的数学名字，47 天后首轮提取成功。

② 动「别的」· ⭐ 三次摔→站起

既没改 N 也没改 P

首答「动 P 和 N」❌（第三次摔）。复述后自己说出「既没改 N 也没改 P」✅。

关键洞察：之前把效果（有效 p 升、N 降）当成了招式。

③ 三件套 · ✅ 修正后全中

可中断 · 可恢复 · 可指导

首答「可重试·可恢复·可打断」——把 checkpoint 的机制（重试）串门进三件套。修正后全中。

可指导 = 重试有方向（带错误信息，非盲重试）。

SECTION 03 ─── Q3 · 钥匙跨域迁移 · 代码审查 Agent

钥匙从客服对话
迁移到代码审查

场景：多轮代码审查 Agent，每轮读历史对话 + 当前 PR diff，轮数越多审查质量越下降。
学习者判定为指数问题，并设计 上下文 checkpoint + 裁判审批 方案。 7/9 在客服场景用过的钥匙，换到代码审查照样掏得出来。

(a) 线性还是指数 · ✅ 结论对

乘法累积 → 指数

每轮信息要「穿过」后面所有轮的注意力才能留下。信息保真度 ≈ p^N——乘法累积，所以是指数。

首答点出链式依赖 + Lost in the Middle，但缺「乘 vs 加」一句话，补全后完美收口。

(b) 对抗方案 · ✅ 钥匙迁移

函数边界 checkpoint + 裁判

按「每个函数」切段（局部低阶 N）→ 审查完 = 存档点 → 清空上下文 → 裁判（模型/人类）审批后继续。

亮点：把 checkpoint 同时用成审批关卡（HITL），不止是存档点。

上下文 checkpoint 骨架 · save → reset → continue：

  审查函数 A
      ↓
  save     持久化审查结论/决策        ← 首答漏了这一步，补全
      ↓
  reset    清空上下文窗口（恢复干净窗口）
      ↓
  continue 带结论进下一段（审查函数 B）
      ↓
  裁判审批（模型 / 人类）── 可信赖 Agent 的 HITL 关卡

  ───────────────────────────────────────────
  错误累积 checkpoint          代码审查 checkpoint
  执行 N 步                    审查 N 个函数
  插存档点                     函数边界 = 存档点
  局部低阶 N                   每段 ≤ 单函数
  同一把「动别的」钥匙，迁移成功
7/9 客服场景 → 7/17 代码审查场景，同一把钥匙两次跨域工作。 它不再只属于「错误累积」那一章——成了拆所有「链式过程」的通用工具。

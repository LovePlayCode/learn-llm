SECTION 01 · 可观测性价值

四大价值维度 · 引导后补全

排查定位 (Debug)

精确到哪一步慢、哪一步贵、哪一步错。从黑盒变成玻璃盒。

成本管理

查看每步花费，发现哪些步骤不经济。数据驱动的成本优化。

持续改进 / 迭代闭环

安全合规审计

Trace 记录每步输入输出，合规团队可审计 Agent 是否越权/泄密/决策可解释。引导后补出。

SECTION 02 · 多代理 × Trace

树更深更宽 · 但仍是一个 Trace

单 Agent：
Trace
 └─ Span: Agent
      └─ Span: Tool A
      └─ Span: Tool B

多代理（Controller + 专业 Agent）：
Trace
 └─ Span: Controller Agent
      └─ Span: 专业 Agent A       ← 更宽（多个并行兄弟 Span）
           └─ Span: 子步骤 A1     ← 更深（嵌套更多层）
           └─ Span: 子步骤 A2
      └─ Span: 专业 Agent B
           └─ Span: 子步骤 B1
      └─ Span: 专业 Agent C
           └─ Span: 子步骤 C1
           └─ Span: 子步骤 C2

关键：一个用户任务 = 一个 Trace，无论多少 Agent 参与。

答题表现

方向全对："树形""一个根 Trace""Span 嵌套 Span""更深更宽"都答出。未画 ASCII 图，D30 追击。

SECTION 03 · 评估闭环 × 错误累积

提高 p + 定位后切短 N

评估闭环如何作用于 1 - p^N：

路径 A：提高 p
  发现失败 case → 回流离线 → 优化 Prompt/Tool → p 提高
  （跨时间迭代，每轮让 Agent 更好）

路径 B：切短 N
  在线监控定位第 3 步总出错 → 加 checkpoint → N 从 8 切成 3+3+2
  （可观测性是前提，不知道哪步出错就不知道在哪加 checkpoint）

⚠️ 区分：
  checkpoint = 运行时即时拦截（Controllable 的儿子）
  评估闭环 = 跨时间迭代改进（持续优化循环）

修正过程

第一轮把 checkpoint 和评估闭环混为一谈（把"固定节点检查"说成评估闭环）。经引导后分清：一个是运行时即时拦截，一个是跨时间迭代。修正后两条路径都答对。

SECTION 04 · 缓存围栏 × 三兄弟

同一事件的不同视角

缓存三兄弟（回答"怎么命中"——机制分类）：
  精确缓存 ─── 字符完全匹配
  语义缓存 ─── 向量相似度匹配
  提示词缓存 ── 前缀匹配，省 self-attention

缓存做围栏（回答"放在哪/干什么"——架构角色）：
  用户请求 → 缓存层先拦 → 命中？直接返回
                            └─ 未命中 → 路由 → 大/小模型

关系：同一件事（缓存），不同切面：
  三兄弟 = 内部机制细节
  做围栏 = 外部架构定位

自我修正亮点

第一反应说"上下层关系"，经引导后自主修正为"同一事件不同视角"。这个修正过程本身展示了好的元认知——能质疑自己第一版答案并重新定位。

01 · tcc 三大准则

TCC · 第 5 次毕业（含深度盲点修复）

英文缩写 4 次全丢 → 第 5 次一字不差 ｜ Consistency 3 次盲点 → "老朋友"焊死

毕业英文缩写

Transparent · Control · Consistency

历史：5/7 丢、5/11 丢 → 5/16 一次答对

毕业T+C 搭配原因

只有 T 没有 C → 被监视感
只有 C 没有 T → 无力感

从 5/11 "干着急" 升级到 "被监视"——精准命名

深度修复Consistency = "行为可预期"

盲点历史：5/7 "可复现" ❌ → 5/11 "可复现" ❌ → 5/16 "质量一致" ❌
诊断：语义槽位空缺 + 日常直觉翻译（看到 Consistency 自动捞"一致 → 结果一致"）
焊死钩子："老朋友"——我熟悉它，我知道它会怎么处理事情。行为可预期。

元层级收获：输入端的钉子（防止"日常直觉翻译"）

以后遇到专有术语，先问自己："这个词在特定上下文的作用？"——而不是先想它中文是什么意思。

进阶版（套用 5/11 分层钥匙）：先问"它的爷爷是谁？兄弟是谁？工具是谁？"——让术语自动落到三层结构里。

T 和 C 含义小修正（已告知，需口头固化）

T（Transparent）：智能体的思考/决策过程对用户透明（不是"工作"，是"过程"）

C（Control）：用户能中断 / 继续 / 干预智能体的执行流程（不是泛泛的"可控制"，是细颗粒操作动作）

03 · 解耦三条工程好处

解耦三条 · 第 6 次毕业（含代码验证）

"定规则"从理解偏了到"不用动 LLM 就可以改变 LLM 的行为"——工程收益思维跃迁

最终答案

条目名称好处
1换大脑不动骨架和规则，只换 LLM
2搭骨架复用（模块化，不同 Agent 反复使用）
3定规则不用动 LLM 就可以改变 LLM 的行为
"定规则"的历史错答轨迹
日期答案问题
5/7"先写规则再选工具"描述的是操作顺序，不是好处
5/11"先写规则再选工具"同上
5/16"不用动 LLM 就可以改变行为"✅ 工程收益思维

🔑 钩子："遥控器"——不拆电视（模型），拿遥控器（规则）就能换台（行为）。

代码验证：decoupled-agent.ts（已生成）

文件位置：learn/demos/decoupled-agent.ts

演示 4 个场景：

1. 组装客服 Agent = Claude 大脑 + 客服规则 + 通用骨架

2. 换大脑：agent.swapBrain(new LocalBrain()) — 一行搞定

3. 定规则：agent.swapRules(creativeWriterRules) — 一行搞定

4. 搭骨架复用：new AgentSkeleton(任意大脑, 任意规则)

运行命令：npx tsx learn/demos/decoupled-agent.ts

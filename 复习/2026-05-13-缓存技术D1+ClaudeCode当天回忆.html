SECTION 02 ─── 概念对比 · 精确缓存 vs 语义缓存

一个比字符串，一个比语义

精确缓存

比的是字符完全一致

命中 → 直接返回

未命中 → 处理 + 存 + 返回

无前置判断费

语义缓存

比的是意思相近

三步：嵌入 → 向量搜索 → 阈值判断

命中率天花板高，但坑也多

"先交保护费" · 不管命不命中都付判断费

SECTION 03 ─── 语义缓存三类坑 · 必须焊死的口诀

质量 · 性能 · 安全

┌─────────────────────────────────────────────────────┐ │ 语义缓存的 5~7 个坑 → 归纳为 3 个抽屉 │ ├─────────────────────────────────────────────────────┤ │ │ │ 质量（判断准不准） │ │ ├── 嵌入向量质量差 │ │ ├── 向量搜索质量差（不准，不是慢！） │ │ ├── 相似度度量标准不可靠 │ │ └── 阈值难调 │ │ │ │ 性能（判断贵不贵） │ │ ├── 每次查询都要跑一次向量搜索 │ │ └── 缓存越大，搜索越慢、越贵 │ │ │ │ 安全（该不该缓存） │ │ ├── 用户专属查询 → 数据泄露 │ │ └── 时效性查询 → 返回过期答案 │ │ │ └─────────────────────────────────────────────────────┘ 记忆口诀：质量 · 性能 · 安全 分类依据：不准 → 质量 ❌🎯 | 不快/贵 → 性能 💰 | 出事 → 安全 🚨

今日易错点

第一次作答时把"搜索慢"归到了质量抽屉 → 慢是性能问题，不是质量问题。

质量抽屉里那个坑是"向量搜索质量差"= 搜出来的结果不准。

不准 → 质量 ｜ 不快 → 性能 ｜ 出事 → 安全

SECTION 06 ─── 今日最佳表述

Plan Mode 的错误成本降维

"将'犯错回退操作步骤'这类成本比较高的操作，回退为'犯错回退计划'"

——学习者原话。精准捕捉了 Plan Mode 的核心价值：不是"帮你想清楚"这种空话，而是错误成本从"实操代价"降维为"纸面代价"。

SECTION 07 ─── 横向连接

缓存 × Claude Code × RAG 的共同主题

缓存的"安全坑" ↔ RAG 的"数据泄露风险"

语义缓存的安全抽屉（个人数据泄露）和 RAG 系统中的数据隔离问题是同一类工程风险：用户 A 的数据被错误地返回给用户 B。

解决思路也类似：前置过滤器 + 权限隔离。

Claude Code 的 context 管理 ↔ RAG 的分块策略

两者的底层矛盾一样：窗口有限，信息无限。

RAG 用分块 + 检索来筛选；Claude Code 用 /clear + subagents + Plan Mode 来控制。

核心洞察：context 稀缺性是 AI 工程的统一主题。

"上下兄弟"工具在今天两个话题中的运用

缓存话题：三类坑本身就是分层——质量/性能/安全是同级兄弟，都属于"语义缓存风险"这个爷爷。

Claude Code 话题：/clear、subagents、Plan Mode 是三兄弟，都属于"context 管理工具"这个爷爷，底层工具是 token 窗口机制。

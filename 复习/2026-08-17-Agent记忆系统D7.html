① 提取 ✓ / 更新决策 ✓，但答成"增删改查"——查是情报员的读路径，不在写流水线（读写分层）。 亮点："删"（遗忘能力）在 7 天后仍然留存，初学当天的高光时刻还亮着。 ② 图=关系穿梭 ✓；精确匹配 initially 误答向量 → 修正为 KV（key 进 value 出，一是一二是二）。 ③ 本质答对（三种存取方式根本不同），并自发补充构建成本视角（向量最贵）——课本外的工程洞察； 精修：图也不便宜（抽实体关系要靠 LLM），真正便宜到家的是 KV。 

写路径（两阶段流水线）：提取（LLM总结对话→记忆片段） → 更新决策（加 / 改 / 删）
读路径（不在流水线内）：情报员检索 → 注入上下文

向量 = 模糊语义相似  → 情节记忆（"和这经历类似的"）
图   = 实体关系穿梭  → 实体记忆·关系面（"小王关联哪些偏好"）
KV   = 精确匹配      → 实体记忆·事实面（"小王住哪个城市"）
角色记忆 = 每轮直接注入 system prompt（基本不靠"查"）

B3 知识 Agent ⊆ 上下文工程 · 补丁后通过 ✓

方向正确但踩了术语陷阱：答成"提示词构建"——那是静态阵营的词！ 正确归属：检索→注入 = 上下文工程的动态注入策略（运行时按需给药）。 五种上下文类型已补讲：指令 / 知识（★长期记忆挂此户）/ 工具 / 对话历史 / 用户偏好—— 知识 Agent 只管"长期记忆"这一种信息来源，注入后成为"知识"类型的一部分，故为真子集。 

上下文工程（管整个窗口的全部信息流 · 运行时动态调配）
   ├── ⊇ 提示工程（产出 = 五种类型第①类"指令"，静态写好交运行时管理）
   └── ⊇ 知识 Agent（管"知识/记忆"类型的检索→注入）

🔑 对立是教学手法，包含才是事实结构。
   提示工程 = 开工前写剧本（设计期·静态）；上下文工程 = 演出中当导播（运行期·动态）
   ⚠️ 术语警报：提示词注入(Prompt Injection) = 安全攻击术语，与提示工程不同户口
